## 加油包卡片 3D 倾斜「消失」根因与修复（2026-10-28）
- 倾斜逻辑本身没坏：`initCardTiltParallax()`（index.html ~13830）统一处理 `.step-hero-card/.why-card/.gallery-card/.pricing-card/.boost-card`，6° 上限 + translateZ(8px) + 聚光 sheen。

## 阿里云短信真机接入（2026-10-28 02:45，已联调通过）
### 架构
- 新文件 `apps/web/server/smsProvider.mjs`：阿里云「号码认证」Dypnsapi 双接口封装。
  - `sendVerifyCode(phone)` → `SendSmsVerifyCode`（PhoneNumber/SignName/TemplateCode/TemplateParam/CodeLength/ValidTime/Interval/ReturnVerifyCode=false）
  - `checkVerifyCode(phone, code)` → `CheckSmsVerifyCode`
  - `smsStatus()` → 启动自检（mock / 就绪 / 缺哪些 env）
  - 签名：RPC V1（HMAC-SHA1），percentEncode 必须把 `+`→`%20`、`*`→`%2A`、`%7E`→`~`
- 验证码由阿里云生成并托管，**本服务不持有明文**；本地 `smsCodes` 只记频控 sentAt 与失败次数 fails。
- `JX_AUTH_TEST=1` 或 `JX_SMS_PROVIDER=mock` → 本地 mock（devCode 回传前端自动填），线上必须 =0。

### 实测踩到的三个坑
1. **传 `CodeType:'1'` 会返回 `Code=UNKNOWN / Message=UNKNOWN`**，去掉即正常。该参数不是这个接口的合法名。
2. **正确码校验返回 `{"Code":"OK","Model":{"VerifyResult":"PASS"}}`**，没有 `Pass` 字段。只判 `Model.Pass===true` 会导致「正确码也登不进」。
3. **错误码校验返回 `{"Code":"isv.ValidateFail","Message":"验证失败"}`**，若按 `Code !== 'OK'` 当通道异常处理，用户输错一次会看到「短信服务不可用」，且 fails 计数不增加。必须单独识别为 `passed:false`。

### 实测结果
- 签名连通：非法号 10000000000 → `biz.FREQUENCY`（签名已通过，只是频控）✓
- 真实下发 13888888888 → `{Code:"OK", Model:{VerifyCode:..., BizId:...}}`，短信真到达 ✓
- 服务端接口：`send-code` → `{channel:'aliyun', ttl:600}` 无 devCode；60s 内重发 → 429；错码登录 → 401「验证码不正确」✓
- 启动日志新增短信通道自检行（mock 警告 / aliyun 就绪 / 未就绪报缺哪些 env）。
- 本流程内实际往 13888888888 发了 3 条真实短信（联调必要消耗）。

- IP 级短信配额：`SMS_IP_HOURLY_MAX`（默认 10）、`SMS_IP_DAILY_MAX`（默认 50），按 `clientIpOf(req)`（TRUST_PROXY=1 才采信 XFF）。原因：全局 API 限流是 10s/50 次，等于 10 秒能刷 50 条付费短信。
