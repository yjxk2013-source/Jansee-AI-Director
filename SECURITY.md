# Security Policy

## Supported versions

Security fixes are applied to the active V4 development line. Production support begins only after a production release is explicitly announced.

## Reporting a vulnerability

Do not publish exploitable details in public issues. Use GitHub's private vulnerability reporting for this repository when enabled, or contact the repository maintainers through a private channel.

Please include:
- affected component and version / commit;
- impact and realistic attack scenario;
- minimal reproduction steps;
- suggested mitigation, if known.

Do not include real customer media, credentials, payment details, or other personal data in a report.

## Response principles

- Triage security reports before feature work.
- Reproduce in an isolated environment.
- Never test against production users or data without explicit authorization.
- Keep exploit details private until a fix and coordinated disclosure are ready.
