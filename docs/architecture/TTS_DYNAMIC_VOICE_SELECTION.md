# JANSEE V4 — 腾讯 TTS 动态音色候选筛选规则

> 状态：产品/技术规则已确认，2026-11-18。本文是音色候选筛选的唯一决策基线。  
> 适用范围：V4 Director Prompt Assembly、腾讯 TTS 音色目录与健康探测。  
> 本规则不代表已完成代码接线或生产验证；实现状态见文末。

## 1. 核心原则

**系统先筛选真实可用的腾讯 TTS 音色候选，LLM 再从候选中作最终导演选择。**

每次发给 LLM 的候选项必须是腾讯云官方真实 VoiceType 数字 ID，不能使用抽象气质 key、微软 Edge ShortName、内部别名、虚构 ID 或未登记 ID。

音色目录登记只证明该 ID 是已知候选，不证明当前可用。只有健康探测状态明确为 `healthy` 的音色，才允许进入新任务的 LLM 候选列表。状态为 `unavailable`、`unknown`、从未探测或健康记录过期的音色一律不进入候选。

LLM 输出的 `voice_id` 必须是候选列表中的原始数字 VoiceType。服务端再次校验候选归属、语言、用户明确指定的性别/语言以及健康状态；不匹配时拒绝该导演方案并重新规划或走明确失败路径，禁止静默改成默认女声。

## 2. 每次动态筛选流程

### 第一步：场景与角色边界

- 带货（`online-ecommerce`）：只允许电商人设及其兼容的电商主播 DNA；音色候选不得绕过主播兼容约束。
- 探店（`physical-store`）：只允许实体人设及其兼容的实体角色 DNA；不得混入电商主播。
- 个人创作（`personal-creation`）：必须 `anchor=none`，不允许任何商业主播/实体角色进入；由宪法导演负责。个人创作仍可从健康的通用腾讯音色中选择配音，不等于禁止 TTS 配音。

场景/人设/主播边界由导演路由规则决定，音色筛选器不得重新分类用户选择的场景，也不得替代人设导演。

### 第二步：语言硬过滤

- 用户明确指定粤语：只提供腾讯官方已登记、明确支持粤语且当前健康的候选。不得混入普通话或英语音色。
- 用户明确指定英语：只提供明确支持英语且当前健康的候选。不得混入普通话专用音色。
- 用户未明确指定外语：默认从健康的普通话候选中筛选。
- 其他语言：只有目录中有明确语言能力且健康的真实音色才可入选；否则明确说明当前无可用音色，不得凑数或冒充。

语言是硬约束，不能通过排序权重抵消。

### 第三步：性别硬过滤

用户明确指定男声或女声时，只提供对应性别的健康候选。用户未指定时，允许男女声同时进入候选，由 LLM 结合内容与表达需要决策。

### 第四步：候选排序与数量

- 普通话默认候选上限为 8 个；从全部符合语言、性别和健康条件的音色中动态筛选，而不是固定永远使用同一组 8 个。
- 粤语、英语分别从各自真实支持该语言且健康的音色池筛选；候选不足 8 个时提供全部合格候选，绝不为凑数混入不兼容音色。
- 候选排序可参考场景、人设/主播 DNA、经真实听辨验证的音色特征与用户明确偏好。
- 音色特征必须来自真实音频听辨或可靠数据，不得仅凭音色名称臆测“高级、温柔、磁性”等属性。
- 当前没有经过盲听校准的权重，不得把暂定权重写成已验证算法。候选排序不得改变场景、人设或主播身份。

### 第五步：LLM 最终导演决策

LLM 只从本次提示词明确给出的候选 VoiceType 中选择一个数字 ID，并决定：
- `voice_id`：最终腾讯 VoiceType 数字 ID；
- `speech_speed`：按内容密度、情绪和节奏决定；
- 旁白表达、情绪与语气：由导演结合内容和角色 DNA 决策。

筛选器不替 LLM 决定语速、情绪或表达方式。

## 3. 健康状态与故障保护

- 每天北京时间 04:00 对登记的腾讯音色执行真实 TTS 探测。
- 新任务只使用健康状态明确为 `healthy` 的音色。
- 探测失败的音色下架；恢复并重新探测成功后才重新进入候选池。
- 运行中合成失败时，只有存在同语言、同性别且明确健康的替补音色才允许替补；否则任务明确失败，不得跨语言替补。
- 目录中登记的 VoiceType 必须有对应语言、性别等元数据；多语言能力必须按腾讯官方能力登记，不得因同一个 ID 出现在多个列表就推断其支持所有语言。
- 每次导演任务应记录候选 ID 列表、语言过滤结果、健康状态快照和最终选中的 VoiceType，便于复盘。

## 4. 给 LLM 的候选格式

给 LLM 的是数字 ID 和必要的简短元数据，例如：

```text
[腾讯 TTS 可用音色候选；只允许从下列数字 VoiceType 中选择]
男声：403010（云嘉和·温和男声） / 403009（云嘉尔·慵懒男声）
女声：402001（云小团·温柔甜美女声） / 403014（云佳洁·轻熟姐姐）
voice_id 必须原样输出上述某个数字 ID，不得输出别名或自行编造。
```

以上仅为格式示例，不代表这些 ID 在任意时刻都健康可用。实际候选必须由当次健康快照动态生成。

## 5. 验收标准

1. 每次发给 LLM 的音色候选全部为腾讯真实数字 VoiceType。
2. 每个候选在本次提示词生成时的健康状态必须明确为 `healthy`。
3. 用户指定粤语/英语时，候选只包含明确支持该语言的音色。
4. 用户指定性别时，候选只包含对应性别音色。
5. 普通话候选最多 8 个；外语候选不足 8 个时不凑数。
6. LLM 输出不在本次候选集中的 VoiceType 时，服务端拒绝，不静默替换。
7. 合成失败替补不得跨语言、跨性别。
8. 个人创作保持 `anchor=none`；商业场景保持既定人设/主播兼容规则。
9. 语速、情绪与表达由 LLM 决定，筛选器不接管。
10. 单元测试覆盖语言、性别、健康状态、候选上限、候选不足、非法 ID、场景主播边界和替补边界。

## 6. 当前代码核对结果（2026-11-18）

本次落盘前只读检查发现：

- `prompt-assembly.ts` 已向 LLM 输出腾讯数字 VoiceType，而不是只输出音色语义别名；普通话候选来自当前音色选项目录。
- 粤语/英语当前提示词路径仍存在直接锁定单个音色 ID 的逻辑，并非“把该语言所有健康候选交给 LLM 选择”。
- `voices.js` 当前 `isTencentVoiceAvailable` 对没有健康记录的 ID 返回可用；这不满足本文“必须明确 healthy 才能进入新任务候选”的规则。
- 当前目录中存在同一个 VoiceType 多语言记录（如中英双语 ID 被拆成多个语言项），后续实现必须按腾讯官方语言能力建模，不能把重复记录当成独立音色。
- 当前工作分支为 `fix/director-scene-routing`，工作区有大量既有未提交修改；`apps/api/src/director.ts` 也存在已知构建问题。因此本次只落盘规则，不覆盖或重写现有导演文件，不声称动态筛选代码已完成。

**结论：规则已确认并写入项目文档；代码实现仍需按上述验收标准补齐并测试，当前不能保证所有语言路径都已向 LLM 传递完整的动态候选集。**


## 7. 实现状态更新（2026-11-18）

本节覆盖并更新第 6 节中“后续实现”的状态说明：

- `voices.js` 新增 `getAvailableTencentVoiceCandidates`：按语言、性别、候选上限与人设倾向生成去重候选；普通话未指定性别时尽量保持男女各半，最多 8 个；英语/粤语只返回语言匹配候选，不凑数。
- 新任务的健康判断改为仅接受明确的 `healthy`；未探测、`unknown`、`unavailable` 均不进入候选。
- 启动加载时，超过 24 小时的健康记录按 `unknown` 处理，避免用过期健康状态继续向 LLM 暴露音色。
- 健康探测结果为 `unknown` 时会将当前状态同步为 `unknown`，不再保留旧的 `healthy` 状态。
- Director Prompt Assembly 已将动态候选列表交给 LLM；粤语/英语不再直接锁定单个 ID。
- Director 接收 LLM 结果后，要求 `voice_id` 必须属于本次按同一规则生成的候选集，且仍为明确健康状态；不匹配即拒绝，不允许通过映射层静默换成其他 ID。
- 启发式兜底也只从当次合格候选集中选取音色；无合格候选时明确失败。
- 个人创作的 `anchor=none`、带货/探店的人设角色路由未改变；语速仍由导演输出 `speech_speed`。

本次本地验证：音色目录与导演契约专项测试 9/9 通过；`npm run typecheck` 通过；`npm run build --workspace @jansee/api` 通过。尚未部署，也未在本次改动后重新调用腾讯云线上接口做 26 个音色的实时探测。生产环境仍以健康表最新探测结果为准。
