# 简兮 AI 导演宪法 · 音效版块 V2

> 本版仅定义音频与音效规则。视觉镜头、画面构图、素材选择、转场视觉效果等规则留待后续视觉版块制定，不在本版重复规定。

## 0. 核心原则与职责边界

1. **成片表达优先于音效使用率。** 不得为了用完音效库而强行添加音效。
2. **配音清晰度优先。** 音效和背景音乐不得掩盖人声、关键信息或原始视频中必须保留的声音。
3. **大模型负责规划，程序负责执行。** 大模型可以规划音频表达、情绪和大致使用时机；具体音效文件选择、时长读取、轮换、时间线约束、混音和使用记录由程序处理，不为每个音效单独调用大模型。
4. **尊重现有数据契约。** 必须遵守项目当前正式 JSON Schema；不得擅自添加未经支持的字段。
5. **不得假设资源存在。** 音效、配音、背景音乐或分类目录不存在或不可用时，按程序定义的安全回退策略处理，不得虚构资源。
6. 本版只管音频规则，不定义视觉场景、画面素材、镜头运动、颜色、画面转场或其他视觉规则。

## 1. 音效库管理

1. 音效库使用独立的 MP3 文件，不需要把音效转成视频。
2. 为每个音效维护元数据，至少包括：唯一 ID、文件路径、原始类别、实际时长、是否启用、已使用状态或轮换记录。
3. 实际时长由 FFprobe 等媒体工具读取，不以文件名或人工估算值代替。
4. **素材库可以保留全部 60 种音效，但不要求全部启用。** 应通过试听和实际成片验证建立启用白名单。暂不启用的文件可以保留为备用，不必物理删除。
5. 不得仅为追求轮换或素材使用率而调用不合适的音效。

## 2. 音效用途分类与调用规则

> **V2 定版（2026-10，用户验收后落盘）**：图片成片链路实际只启用**三类点触音效**，
> 时间点固定：片头 intro_sfx（t=0）、转场 transition_sfx（每个切点前 0.1s）、
> 片尾 outro_sfx（末尾 1.5s 淡出前）；强度由导演契约 `sfx.intensity`（0.3~1.2）统一控制。
> 下文 2.1~2.6 为类别级选型参考，实际铺轨以三类时间点为准；Emphasis / Build-up / Ambience 暂不启用。
> 勘误（2026-10-13 阶段三契约审计）：`sfx.intensity` 并非 LLM 输出契约字段——LLM 写入链未接通，
> 运行时强度恒走程序默认值 0.8（详见第 11 节登记）；上句「导演契约」表述按历史记录保留。

### 2.1 开场音效（Opening）

- 主要候选原始类别：起势渐强、高级感光效、冲击强调、科技电子。
- 用途：视频开头需要建立节奏、产品首次亮相或开场需要强调时。
- 优先选择短促、起止清楚、与作品风格一致的音效。
- 不要求每条视频都使用开场音效。
- 避免使用过长的渐强音、过重的冲击音，或遮盖开场配音的声音。

### 2.2 转场音效（Transition）

- 主要候选原始类别：转场音效、高级感光效、部分科技电子。
- 用途：适合的镜头切换、场景变化或段落衔接时。
- 优先选择短促、干净、起止明确的音效。
- 不得在每次切镜时自动添加音效；应根据节奏、风格和配音情况决定是否使用。
- 避免尾音拖沓、持续时间过长或听感突兀的音效。

### 2.3 卖点强调音效（Emphasis）

- 主要候选原始类别：冲击强调、高级感光效、部分科技电子。
- 用途：关键卖点、重点信息或重要展示节点需要突出时。
- 可选择短促低频冲击、清脆提示或轻微闪亮类音效，实际选择以文件试听结果为准。
- 只用于少数关键节点，避免每个卖点连续使用重击音，也避免不符合品牌气质的夸张音效。

### 2.4 氛围铺垫音效（Build-up）

- 主要候选原始类别：起势渐强、星空宇宙、部分科技电子。
- 用途：情绪逐步提升、重要信息揭晓前或需要蓄势的段落。
- 必须考虑实际可用时长；短镜头中不得强行塞入完整渐强过程。
- 若氛围音效与作品风格不符，则不使用。

### 2.5 环境氛围音效（Ambience）

- 主要候选原始类别：自然环境、星空宇宙。
- 用途：视频内容确实需要自然环境、空间感或特定情境氛围时。
- 必须与内容和整体声音风格相匹配，不得把自然环境声或宇宙音效默认铺在所有带货视频上。
- 只有在音质、长度和场景适配时，才可将较长的环境音效适度循环；循环不得产生明显接缝或干扰配音。

### 2.6 结尾音效（Ending）

- 主要候选原始类别：收尾音效、高级感光效、部分冲击强调。
- 用途：视频结尾、品牌展示结束或音频需要明确收束时。
- 优先选择干净收束、轻柔余韵或短促落点类音效。
- 若背景音乐本身已经自然收束，或结尾音效会造成声音拥挤，则允许不加。
- 音效不得被生硬截断，也不得超出成片时间线。

### 2.7 原始类别与用途映射

| 原始音效类别 | 主要用途 | 次要用途 | 默认策略 |
|---|---|---|---|
| 转场音效 | 转场 | 场景/段落衔接 | 优先筛选启用 |
| 冲击强调 | 卖点强调 | 开场、结尾落点 | 精选启用 |
| 起势渐强 | 开场、揭晓前铺垫 | 情绪提升 | 精选启用 |
| 星空宇宙 | 特定空间氛围 | 氛围铺垫 | 场景匹配时使用 |
| 自然环境 | 自然场景氛围 | 情境铺垫 | 场景匹配时使用 |
| 高级感光效 | 开场、转场、结尾 | 产品强调 | 优先试听筛选 |
| 科技电子 | 科技类内容、卖点强调 | 开场、转场 | 按内容风格启用 |
| 收尾音效 | 结尾收束 | 品牌展示结束 | 优先筛选启用 |

以上为类别级候选映射，不代表原始类别中的每个文件都已经通过试听审核。每个文件的最终用途必须根据实际听感、时长、音质和成片效果确认。

## 3. 时长、时间线与轮换

1. 使用实际读取的音效时长进行排程，不得仅凭类别推断时长。
2. 短音效不得为填满镜头而强行拉长；较长音效可按需要裁剪并合理淡出。
3. 音效不得超出成片时间线。时间线不足以容纳音效时，应缩短、跳过或改选。
4. 音效不需要覆盖每个镜头；应优先保留配音清晰度和声音层次。
5. 按用途类别维护独立轮换记录，尽量避免连续作品重复使用同一个音效。
6. 仅在合成成功后，才将对应音效记录为已使用；失败的合成不得消耗轮换状态。
7. 某类别所有已启用音效均轮换使用后，可重置该类别记录并重新打乱顺序。
8. 如有并发生成任务，轮换状态更新必须避免并发任务重复领取或覆盖记录；具体实现遵循项目现有存储与事务方案。
9. **人声第一优先避让铁律（2026-10-12 定版）**：音效与 TTS 人声重叠时必须第一时间让路。
   两层机制：① 排程层（audio/sfx.js buildSfxTimeline 接收 voiceRanges）——转场音效整段前移
   播在人声开始之前（whoosh 引导切点，不早于上一镜切点）；片尾音效贴最后一句人声结束后起播。
   ② 混音层兜底（core/composer.js）——仍与人声重叠的音效在人声起点前 0.05s 截断（atrim）
   并加 0.12s 快速淡出防爆音；截后不足 0.15s 的直接丢弃。

## 4. 背景音乐（BGM）

> **LLM 大导演定版（2026-10-12，最高优先级）：BGM 回归图片成片链路**，推翻 2026-10 早期
> 「图片成片无 BGM」铁律。导演契约 `bgm_emotion` 字段回归（情绪池 9 个：luxury / warm /
> calm_narrative / relaxed / tech_future / fresh / inspirational / passionate / generic），
> 曲库全量落盘 `materials/audio/`（31 情绪 × 4 首，自云服务器拉回）。选曲唯一入口
> `packages/audio-kit/bgm.js` 的 `selectBgmByEmotion`（`modules/image_creator/core/timeline.js` BGM 段消费）：
> 情绪目录内轮转不重复；非法情绪静默落 `generic` 兜底；两段式音量 duck（人声区间
> duckVol 0.10 / 其余 baseVol 0.22，人声永远优先）；结尾 afade 1.5s 淡出。
> 点触音效降为 LLM 可选项：导演 JSON `sfx_on`（缺省 true）整体取舍。

1. 背景音乐应与作品情绪、产品风格和使用模式匹配。
2. 配音期间自动降低背景音乐音量（ducking）；参数集中管理，避免多个模块出现互相冲突的硬编码。
3. 背景音乐长于成片时，应按需要裁剪并淡出；只有适合的音乐才允许循环。
4. 若目标情绪目录没有可用音乐，按项目已有回退规则处理；不得伪造音乐文件或目录。
5. 背景音乐音量、淡入淡出和人声压低参数应以项目正式配置为准，不在宪法中重复维护多套冲突数值。

## 5. 原始音频与 AI 配音

1. “保留原视频/原音频”路径应遵守现有业务规则，不得擅自重写原始音频内容。
2. 原视频音频同步、ASR 字幕与背景音乐的处理应保持职责清晰，不得因为添加音效而破坏同步。
3. AI 配音路径应根据视频实际时长规划文案和音频节奏；语速估算仅作规划参考，最终以 TTS 实际结果和时间线校验为准。
4. 语音 ID 必须来自项目实际可用的语音资源清单，不得虚构 ID。
5. 配音、背景音乐和音效的最终混音由音频合成程序执行。

## 6. 商业表达与音频风格

1. 音效只用于辅助表达，不得替代或夸大产品事实。
2. 不得仅因音效听起来“高级”就强行用于不匹配的产品风格。
3. 需要克制、可信或专业表达时，优先采用简洁、低存在感的音效，必要时不加音效。
4. 不同作品可以有不同音效密度；不得规定每条视频必须使用固定数量的音效。

## 7. JSON 输出契约

1. 生成任务必须遵守项目当前正式 JSON Schema 和调用方接口约定。
2. 如果当前 Schema 没有音效选择字段，不得擅自增加 `sfx_id` 等字段；音效可由程序依据类别、时间线和轮换状态调度。
3. 不得为了音效模块破坏既有字段、数据类型或调用方兼容性。
4. 只有在项目正式更新 Schema 并完成相应兼容实现后，才可新增结构化音效规划字段。
5. **音效与 BGM 契约（LLM 导演定版 2026-10-12）**：导演 JSON 现包含 `sfx: { intensity, intro, transition, outro }`
   字段（intensity 0.3~1.2，三个开关分别控制片头/转场/片尾音效），以及 `sfx_on`（bool，缺省 true，
   整体取舍点触音效）、`bgm_emotion`（情绪目录名）、`bgm_on`（bool，缺省 true）——`bgm_emotion`
   已随 BGM 回归重新纳入正式契约。
   > 勘误（2026-10-13 阶段三契约审计）：本条中 `sfx: { intensity, intro, transition, outro }` 与实际不符——
   > LLM 输出契约（apps/web/server/prompt/constitution.md §4）无 `sfx` 字段，写入方全零，且代码侧真实
   > 开关名为 `enableIntro / enableTransition / enableOutro`（packages/audio-kit/sfx.js L65-71）；
   > `sfx` 属未接通的预留能力，详见第 11 节。`sfx_on` / `bgm_on` / `bgm_emotion` 三项经审计确认为
   > 有效契约字段，该部分无误。
6. 在要求机器可读 JSON 的任务中，只输出符合既定契约的 JSON，不添加额外说明文字。

## 8. 工程配置与失败回退

1. 音效、BGM、人声混音相关参数应集中管理，避免在多个模块重复硬编码。
2. 修改前先检查项目当前真实目录、配置和合成实现；不得假设 `packages/ffmpeg-kit/constitutionEffects.js` 等路径必然存在。
3. 音效文件缺失、不可读、时长读取失败或解码失败时，应跳过该文件并记录可诊断日志，不能因此导致整条视频无必要地失败。
4. 某用途类别没有可用音效时，允许不加音效；不能把其他类别的音效无条件塞入。
5. 音频处理失败时，按项目既有错误处理和回退策略执行，不得静默产出明显损坏的音轨。

## 9. 音效授权

1. 在将音效用于商业 SaaS、服务器存储、多用户生成和生成视频对外分发前，必须核验许可范围。
2. 记录来源、许可文本、商业用途限制和必要的授权证明。
3. 可下载或可播放不等于允许商业使用、服务器存储或向用户交付生成成片。

3.  **混音与收尾**：TTS 配音与音效 amix 直通混音（normalize=0，不挂响度归一）；

    `modules/image_creator/core/timeline.js`），混音 `packages/ffmpeg-kit/composer.js`（amix），
    效果参数唯一权威来源 `packages/ffmpeg-kit/constitutionEffects.js`。
