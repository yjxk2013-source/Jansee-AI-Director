# 简兮 AI 导演宪法 · 视觉版块 V2

> 版本：V2.0\
> 性质：视觉创作与成片合成的规则基线\
> 适用范围：简兮 AI 视频生成与剪辑链路\
> 核心原则：成片质量优先；导演判断与程序执行分工明确；不为展示特效而牺牲内容。

------------------------------------------------------------------------

## 0. 核心原则与职责边界

1.  **成片质量优先于特效数量。**
    视觉效果必须服务于内容、叙事、节奏和观看体验，不得为了使用某种效果而强行添加。
2.  **镜头连贯性优先于转场花样。**
    能自然直接切镜时，不必增加转场；整条视频可以有变化，但必须保持统一的视觉风格。
3.  **大模型负责创作判断，程序负责确定性执行。**
    大模型可以根据内容规划画面意图、情绪、节奏和衔接方式；素材校验、参数约束、时间线、合成、编码与质量检查由程序完成。
4.  **不为每个视觉效果额外调用大模型。**
    优先复用当前主生成调用的结果和本地规则，不因单个转场、镜头运动或效果选择新增不必要的
    LLM 调用。
5.  **不得假设素材或能力存在。**
    任何素材、滤镜、字体、模板或转场能力，都必须以项目中实际存在且可用的资源和实现为准。
6.  **尊重现有数据契约。** 必须遵守项目正式 JSON
    Schema、接口和参数约定；不得擅自添加未经支持的字段。
7.  **视觉规范与工程参数分层。**
    本文定义视觉原则和决策规则；具体滤镜参数、时长、画幅、编码等数值以项目实际生效的工程参数为准。发现冲突时先报告，不得静默覆盖。
8.  **不得以成本优化为由牺牲明显可感知的成片质量。**
    可以优先使用程序合成和可复用素材，但选择必须以最终观感合格为前提。

## 1. 导演、素材与程序的职责

### 1.1 导演判断

视觉规划应综合考虑： - 视频主题、受众、平台与目标画幅； -
商品或主体的重要卖点； - 画面情绪、视觉重心和叙事顺序； -
前后镜头的构图、色彩、运动方向与节奏； -
旁白、字幕和画面信息之间的关系； - 素材质量、真实时长和可用范围。

导演判断应优先追求清楚、自然、可信和有节奏的表达，而不是堆叠镜头或效果。

### 1.2 程序执行

程序负责： - 检查素材是否存在、可读、时长有效及分辨率是否可用； -
按既定规则检索、匹配、轮换和兜底素材； -
对镜头时长、转场重叠、画面比例和时间线进行约束； -
执行运镜、转场、字幕、淡入淡出和编码（V2 铁律：**不含调色**，见附录 C）； -
保证音画同步、输出时长与文件可播放性； -
在合成后进行可自动化的质量检查。

程序不得把未实现的视觉能力当作已实现功能；导演规划无法执行时，应安全回退到可用方案。

## 2. 视觉叙事与镜头组织

1.  每个镜头必须承担明确作用，例如展示主体、解释卖点、建立场景、补充细节、推进情绪或完成收束。
2.  镜头顺序应服务于内容逻辑，不能只按素材库返回顺序拼接。
3.  商品展示应优先让商品与关键卖点清晰可见，避免装饰性画面长期遮挡主体。
4.  风景、城市、氛围类镜头应建立视觉节奏，但不得用重复的慢镜头和同类构图拖长视频。
5.  镜头数量、单镜时长和整体节奏应根据内容、旁白及目标时长决定，不使用僵硬的固定模板替代判断。
6.  静态图片可以通过轻微推拉或平移增强生命感，但运动幅度应克制，不得产生明显抖动、越界、拉伸或主体变形。
7.  动态视频优先尊重素材原有的运动逻辑；不得为了统一运镜而破坏原视频动作。
8.  每个镜头都应有足够的有效画面时长。不得为了满足转场或特效而把镜头截得过短。

## 3. 素材选择与画面匹配

1.  素材必须与当前镜头的语义、主题和表达目的相关。
2.  相关性优先于素材新奇度；不得为了画面丰富而使用明显无关的素材。
3.  优先使用清晰、主体明确、构图稳定且适合目标画幅的素材。
4.  不得把低清素材强行放大到产生明显像素化的程度；需要填充画幅时，应选择不会明显降低观感的处理方式。
5.  竖屏、横屏素材混用时，应优先保护主体和关键内容，避免无意义的黑边、错误裁切或拉伸变形。
6.  不得重复使用同一素材到令人明显察觉的程度。素材不足时，优先安全回退并保持画面质量，不得伪造素材存在。
7.  资产轮换只能在候选素材同样适用的前提下进行，不能为了轮换牺牲相关性。
8.  AI
    生成素材、用户上传素材、素材库素材应按各自真实属性处理，不得把占位图或缺失资源当成有效画面。

## 4. 运镜规则

1.  运镜的目的在于突出主体、建立空间或改善节奏，而不是让画面持续运动。
2.  静态图片可使用缓慢推近、拉远或平移；应控制幅度与速度，避免机械循环。
3.  连续镜头应尽量避免相邻镜头完全相同的运动模式；但不能为了追求变化而突然反向或无意义晃动。
4.  动态素材已有明确运动时，应优先保留原有运动，不叠加冲突的虚拟运镜。
5.  运镜不得导致主体出框、关键文字被裁切、画面边缘露底或明显变形。
6.  运镜参数必须受素材分辨率、时长和目标画幅约束；参数值以实际工程配置为准。
7.  如果无法安全执行运镜，使用静止画面或其他可用方案，不得输出破损画面。

## 5. 转场规则

### 5.1 总原则

1.  转场是镜头衔接手段，不是必须展示的特效清单。
2.  **默认直接切镜；不需要特效时不添加转场。**
3.  禁止纯随机选择转场，禁止为了展示多样性而在一条视频里轮流使用所有转场。
4.  不要求整条视频统一使用同一种转场。应根据镜头关系选择，但整条视频的节奏与视觉风格必须协调。
5.  转场应优先由程序合成完成，不要求为每一种转场单独生成视频素材，也不得默认调用付费视频生成
    API。
6.  选择转场前必须检查实际引擎能力；文档中定义一种转场，不代表代码已经实现该能力。
7.  转场效果不得破坏主体清晰度、旁白可懂度、音画同步、镜头完整性或目标时长。

### 5.2 P0：基础转场

**A. 直接切镜（Cut）** - 默认首选，额外转场时长为 0。 -
适用于节奏紧凑、动作连续、构图匹配或直接切换更自然的镜头。 -
如果直接切镜已经流畅，不应为了"电影感"额外添加效果。

**B. 交叉叠化（Cross Dissolve）** - 初始建议时长：0.3--0.6
秒；具体值需通过实际成片验证，并以工程参数为准。 -
适用于风景、城市、氛围镜头或需要柔和衔接的场景。 -
只有当前后画面叠加后不会造成明显主体重影、构图冲突或节奏拖沓时才使用。 -
必须正确处理前后镜头重叠时长，避免错误增加或缩短时间线。

**C. 淡入淡出（Fade）** -
用于片头显现、片尾收束或有明确叙事意义的段落边界。 -
不应机械地用于每个镜头连接点。 - 片尾淡出与普通镜头间转场分开管理。

**D. 黑场过渡（Fade Through Black）** - 初始建议黑场时长：0.2--0.4
秒；最终参数以实际工程配置和成片验证为准。 -
用于明确的情绪停顿、章节切换或特殊场景转折。 -
普通镜头切换默认不插入黑场。 -
必须避免意外黑帧、过长停顿或让视频产生卡顿感。

### 5.3 P1：智能增强转场

只有在前后素材条件充分、实际引擎支持且能提升成片时，才考虑使用：

1.  **甩镜转场（Whip
    Pan）**：前后镜头运动方向、速度和模糊趋势能够匹配时使用。
2.  **遮挡转场（Object
    Wipe）**：人物、商品、墙壁或其他前景确实能形成有效遮挡时使用；不得凭空假定遮挡条件存在。
3.  **推拉转场（Zoom
    Transition）**：前后镜头的景别、主体位置和运动能够自然衔接时使用。
4.  **运动匹配转场（Motion
    Match）**：根据运动方向、速度或主体位置建立连续感。
5.  **虚焦转场（Defocus）**：适用于氛围表达或需要柔和衔接的场景，不得让主体长时间失焦。
6.  **匹配剪辑（Match
    Cut）**：利用形状、构图、颜色或主体位置的相似性连接场景。
7.  **动作匹配剪辑（Action
    Match）**：只有动作方向、时间关系和动作连续性成立时使用。

上述类型若当前引擎不支持，不得假称可直接使用；应记录为未来可选能力，不能擅自扩展代码范围。

### 5.4 P2：风格化特效

默认关闭或谨慎使用，必须有明确的题材、节奏或视觉设计理由：

1.  **闪白 / 闪黑（Flash）**：适用于明确的节奏重拍或强烈视觉强调。
2.  **旋转 / 径向模糊转场**：适用于确实需要动态冲击的风格化内容。
3.  **故障转场（Glitch）**：主要适用于科技、游戏等相匹配题材。
4.  **擦除转场（Wipe）**：适用于有明确图形设计语言的广告或风格化视频。

不得为了"看起来高级"而滥用强特效。强特效如果分散注意力、显得廉价或与内容不符，应优先删除。

### 5.5 转场决策顺序

每个镜头连接点依次判断：

1.  直接切镜是否已经自然？自然则直接切镜。
2.  若直接切镜不够自然，判断是否适合交叉叠化。
3.  若存在明确情绪停顿或段落边界，考虑淡入淡出或黑场。
4.  若前后镜头具有明确的运动、遮挡、动作或构图匹配条件，再考虑相应的 P1
    转场。
5.  只有题材和节奏明确需要时，才考虑 P2 特效。
6.  如果素材条件不满足、实现能力不足或效果可能降低画质，回退到直接切镜。

可以在多个同样合适的候选方案中做受约束的选择，但不得纯随机抽取，也不得强行凑齐转场种类。

## 6. 片头、片尾与品牌视觉

> **变体成套设计定版（2026-10-12）**：字体/排版按变体成套分化，layout×font×graphic×color
> 必须满足 rules.js COMBO_RULES 视觉规则矩阵。**排版权全权移交 LLM 导演（2026-10-12 二次定版）**：
> 导演契约 `visual_design`（layout/font/graphic/color/title_form/title_material/animation_in/animation_out
> 八维整套决策，视觉菜单 `rules.js visualMenuTextForLLM()` 随 prompt 下发），封面文案同步由导演决定
> （主标题=title、副标题=cover_line）。工程侧只做兜底清洗：`modules/image_creator/api/visual.js sanitizeVisualDesign`
> 枚举非法/缺失 → 回退黑曜石默认套装；组合越界（layout 不允许的 font/graphic/color）→ 按
> `rules.js LAYOUT_DEFAULT_COMBOS` 回退该布局默认维度——清洗产物保证过视觉引擎强校验，零抛错降级。
> 旧 VARIANT_EDIT_MAP 变体映射已随程序编排层退役，同一规则矩阵下严禁只换 font 不换 layout。
> **大字距（tracking）双限制**：① 仅主标题，副标题永不 tracking（小字号长文本套字距必击穿
> 字号下限）；② 仅 ≤8 字短标题启用，长标题自动放弃（视觉宽度翻倍会超出布局容纳极限）。
> **封面抽帧定版**：compose 完成后在 2.6s（片头层动画入完成、未入首个叠化）抽帧落盘
> cover.jpg——此刻主标题 + 副标题 + 几何元素完整同框，作为成片封面（core/index.js）。

1.  片头应快速建立主题和视觉基调，不应长时间占用内容展示时间。
2.  片头标题、品牌标识、装饰线条和坐标等图形元素应由可控的程序或模板层叠加，避免依赖生成模型在视频中直接绘制精确文字。
3.  动态背景应为标题、标识和必要信息保留足够的视觉空间，避免高细节区域干扰阅读。
4.  装饰元素应按设计规则出现、移动和退出；不得在不需要时永久烙印在整个动态背景中。
5.  片尾应完成内容收束与品牌信息呈现。片尾背景、Logo、标语及淡出应作为可协调的独立层处理。
6.  片尾可使用专门准备的高质量背景素材；是否复用已有素材应以最终观感是否合格为准，不能只为省成本而牺牲效果。
7.  片头或片尾的动态背景素材应检查真实镜头边界和有效片段，不得盲目按预设秒数切片。
8.  品牌元素必须清晰、比例正确，不得拉伸变形、遮挡关键内容或与字幕冲突。

## 7. 画幅、构图与清晰度

1.  输出画幅以当前任务和产品要求为准，不得未经授权改变目标画幅。
2.  保护主体、商品、关键文字与必要的视觉信息。
3.  不得使用非等比拉伸来填满画布。
4.  混合不同画幅素材时，选择合理裁切、背景填充或其他已验证方案；不得默认所有素材都适合相同处理。
5.  避免明显黑边、错误裁切、低清放大、边缘露底、闪烁和主体变形。
6.  **V2 铁律：主画面禁调色。** 不挂 eq/vignette/curves/lut 等任何调色滤镜，素材原色直出；
    旧版「低饱和微高反差 + 暗角」急救包（ENHANCE.chain）已彻底移除，
    严禁在新版链路复挂，防止画面出现「强行曝光」观感。
7.  不得在缺乏验证时宣称某一填充、锐化或调色方案一定更优。

## 8. 字幕与画面信息层级

1.  字幕应清晰、可读，并与画面主体保持合理距离。
2.  字幕、Logo、标题及其他叠加层不得相互遮挡，也不得遮住商品关键特征。
3.  文字区域应考虑目标平台的安全边距与界面遮挡区域。
4.  字体、字号、描边、阴影和位置以项目实际支持的设计配置为准。
5.  不得依赖视频生成模型生成需要准确拼写、品牌一致性或精确布局的文字。
6.  字幕时间应与旁白或实际语音同步，不得因转场重叠而错位、提前消失或重复显示。
7.  画面元素应有明确层级，避免字幕、装饰线条和高对比背景同时争夺注意力。

## 9. 声音与画面的衔接

1.  画面转场不得擅自改变音频时间线。
2.  J-cut、L-cut、Sound Bridge
    等属于音频与剪辑衔接策略，应与画面特效分开管理。
3.  旁白、必要原声和音效按独立音频规范执行。
4.  交叉叠化不意味着必须同时交叉叠化音频；音频处理应根据内容和既有音频规则决定。
5.  任何转场都不得掩盖旁白、造成音量突变或截断必要语音。
6.  视觉效果与音频效果可以协同，但不得为了配合画面转场而违反音效版块的约束。

## 10. 时间线与合成约束

1.  所有转场、镜头运动、淡入淡出、字幕和音频都必须以同一条有效时间线为基础。
2.  转场时长必须受前后镜头真实可用时长约束，不能使用超出素材边界的帧。
3.  叠化必须明确处理重叠时长，防止最终视频时长发生非预期变化。
4.  不得因转场导致末镜缺失、旁白截断、字幕提前结束或时间线错位。
5.  末镜需要补长时，必须使用安全且视觉连续的方式；不得用意外冻结、突兀黑帧或明显重复画面掩盖问题。
6.  不得为了达到目标时长而无限拉长短素材或短音效。
7.  具体时长、帧率、输出分辨率和滤镜数值由项目真实生效的工程配置管理；本宪法不替代这些参数。

## 11. 质量检查与验收

输出成片至少应关注以下问题：

-   素材是否存在、可解码且与镜头内容相关；
-   主体是否清晰，关键卖点是否被遮挡；
-   是否存在明显拉伸、黑边、露底、像素化或画面变形；
-   相邻镜头的切换是否自然，转场是否过度或不合时宜；
-   是否出现意外黑帧、闪烁、明显重影或不合理停顿；
-   运镜是否平稳，有无机械重复、越界或无意义晃动；
-   字幕与旁白是否同步，标题和品牌信息是否可读；
-   音画是否同步，旁白是否完整，音量是否平衡；
-   最终时长是否符合当前任务的约束；
-   输出文件是否能正常播放并包含预期的视频、音频流。

如果自动检查无法可靠判断某项视觉质量，应标注为需要人工预览，不得虚报通过。
