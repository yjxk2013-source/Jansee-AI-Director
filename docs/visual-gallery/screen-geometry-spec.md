## 第零条 · 三条否决项

以下三条任意一条不满足，素材直接作废重出：

1. **必须单镜头。** 10 秒内不许有任何剪辑点、切镜、叠化、闪白、场景变化。一个场景从第一帧撑到最后一帧。
2. **画面里不许出现任何文字。** 包括但不限于：尺寸标注、箭头、尺寸线、参考线、坐标、网格、型号、参数、版本号、品牌名、域名水印、重复铺排的字母组合。屏上、屏框上、墙上、玻璃上、地面上，一律不许有。
3. **机位必须锁死。** 不推、不拉、不摇、不移。屏在画面里的位置一帧不变，像素级恒定。

## 画布基准

| 项 | 值 |
|---|---|
| 分辨率 | 1080 × 1920（竖屏） |
| 帧率 | 30 fps（只能出 24 fps 也可以，合成端统一转换） |
| 时长 | 10 秒 |
| 音轨 | 不需要，交付时请剥除 |
| 坐标系 | 左上角 (0,0)，x 向右，y 向下 |

## 屏的位置与大小

单位：像素（这些数字只用于你在内部构图，**绝对不要画到画面里**）。

| 项 | 值 |
|---|---|
| 形状 | 微竖长方形（宽:高 ≈ 0.911，接近正方） |
| 显示区（内容面板） | 820 × 900 |
| 面板左上角 | x = 130，y = 414 |
| 面板右下角 | x = 950，y = 1314 |
| 面板中心 | (540, 864)，压在画面高度 45% 的那条线上 |
| 边框 | 显示区外面一条很窄的深色边，厚度约为显示区宽度的百分之一到二（14px 上下），能看出一点点厚度和转折，不是平涂的一条线 |
| 屏占画面宽度 | 75.9%（两侧各留 130px 墙体） |
| 屏占画面高度 | 46.9%（上方 414px 是天空与楼体，下方 606px 是街面与地面） |

**屏是画面的主体，但不是全部**：宽度占画面七成半，两侧各留 130px 墙体，上下各留 400–600px 放天空、楼体和街面。它既不能做成"墙中间挂了一幅小画"，也不能顶到画面边缘变成"贴脸拍的广告位"——后者是 912 × 1180 被淘汰的原因。参考图里的构图就是这个比例，照抄即可。

## 面板内容（生成时）

- 面板内只放占位内容，且必须**暗**：平均亮度控制在 25%–35%。
- 内容必须**慢**和**抽象**：模糊色块、暗色渐变缓慢漂移。不允许出现可辨识的场景、街道、楼宇剪影、灯光光斑、高光热点。
- 面板内不得有明暗对比强烈的亮点——会跟后续贴进来的商品抢注意力。
- 占位内容不得溢出面板边界。

## 稳定性

- 屏的位置在整段视频中一帧不变（见第零条第 3 项）。
- 场景其他元素可以动：车流、云、灯光、水面、行人、树影、光的变化。
- 面板内可以有极缓慢的亮度呼吸，但不得有明显位移或闪烁。

## 两侧 130px 窄墙 + 竖向 1020px，真实感要靠这四件事撑

屏宽占画面 76%，两侧各 130px，墙体只能提供有限支撑；上方 414px、下方 606px 才是场景纵深的主要来源（注意不是上下等分——屏中心被刻意压在 45% 线上，所以下方比上方多 192px）。下面四件事必须做足：

1. **边框有厚度**：侧面能看到一点立体感，屏幕有一点点凸出墙面。
2. **投影**：屏在墙面或支架上有方向一致的落影，边缘略软。
3. **光溢**：面板的光把周围墙面、地面染亮一点，越靠近屏越亮。
4. **前景遮挡**：线缆、灯柱、行人、树叶从屏前经过，只压屏角或屏边，**不要压面板中心区域**。

这四件里，光溢和遮挡对"真"的贡献最大。

## 三种用户图片进屏后的尺寸（供理解，不画进背景）

| 用户上传比例 | 等比 contain 后尺寸 | 占面板 | 占画面宽 | 占画布 | 短边 |
|---|---|---|---|---|---|
| 4:3（横图） | 820 × 615 | 68% | 76% | 24.3% | **615** |
| 1:1（方图） | 820 × 820 | 91% | 76% | 32.4% | **820** |
| 3:4（竖图） | 675 × 900 | 82% | 63% | 29.3% | **675** |
| 2:3（竖图，手机竖拍常见） | 600 × 900 | 73% | 56% | 26.0% | **600** |

图片永远完整显示、不裁切；装不满的区域是**真实 letterbox**（黑边或品牌色边），不是模糊底——模糊底等于把设计背景冒充成画面内容，是一眼假的主要来源。留白必须读起来像「有意设计的广告画面」，而不是「尺寸没对上」。

### 判据：两条互补，一条保商品、一条保场景

| 判据 | 阈值 | 管的是什么 | 820×900 | 912×1180 | 900×675 |
|---|---|---|---|---|---|
| 商品短边 | ≥ 580px | 能不能看清商品上的字标 | 615 / 820 / 675 / 600 全过 | 全过 | **506 / 450 不过** |
| 屏占画布 | ≤ 40% | 场景还有没有纵深 | **35.6% 过** | **51.9% 不过** | 29.3% 过 |

不再看「商品占画布面积 ≥30%」。原因：面积是二维量，**对横图过敏**——4:3 面积要凑到 30%，屏宽必须 911、商品横跨 84% 画面宽，那等于逼出一块贴脸巨屏、把场景挤死。

也不再单看「占面板」百分比，那个数分母是屏，屏越小它越高，会给出反向结论（912 × 1180 里横图「占面板」只有 58%，却是占画布最高的那一档）。

**两条的分工**：短边保商品，屏占画布保场景。缺一条就会走极端——只盯短边，会退回 912 × 1180 那种贴脸巨屏；只盯屏占画布，会滑向 900 × 675 那种竖图只剩半个的横屏。两条一起用，同时否掉这两种错法。

## 底部避让

- 抖音全屏 feed 底部实际遮挡约 450px（Tab 栏 + 昵称文案 + 音乐条），安全线在 **y = 1470**；右侧互动按钮列从 **x = 940** 起，纵向 1150–1820。
- 屏的下沿在 y = 1314，**距安全线 1470 还有 156px**，上下都松快。上一版 912 × 1180 的屏底是 1454、只剩 16px，等于贴着边过日子。
- 屏右边缘在 x = 950，比右侧互动列起点 940 超出 10px，重叠区约 10 × 164px，可忽略。**不躲**：为躲按钮缩小或左移屏，是拿商品尺寸换一个本来就不重要的角落。正解是把「文字禁区：x > 930 且 y > 1150」写进屏内广告排版规则，商品居中永远不受影响。

## 素材交付元数据

每段背景视频附一份 JSON：

```json
{
  "canvas": [1080, 1920],
  "slot": { "x": 130, "y": 414, "w": 820, "h": 900 },
  "frame": 14,
  "locked": true,
  "single_shot": true,
  "fps": 30,
  "loop": "seamless",
  "no_annotation": true
}
```

`locked: true` = 屏整段不动；`single_shot: true` = 全片一个镜头；`no_annotation: true` = 画面无任何文字。

## 交付前自检

- [ ] 全片只有一个镜头，中间没有任何切换
- [ ] 画面里一个字都没有（包括屏、屏框、墙、玻璃、地面）
- [ ] 屏是微竖长方形（宽:高 ≈ 0.911），宽占画面 75.9%，两侧各留 130px 墙体
- [ ] 屏的位置一帧都没动过

任何一项不满足，请重新生成，不要交付。
