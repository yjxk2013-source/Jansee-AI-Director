# 图片成片 · 固定模板规格（中间挖洞）

> 定于 2026-10-23。**取代 `image-compose-spec.md` 的版面部分**（那份文档的"海报版面 + 商品区三比例"已被本轮否定，见文末"为什么放弃海报版面"）。
> 打样代码：`storage/tmp/contain/v5.mjs`

## 一、核心变化：条带高度由模板决定，不再由图决定

旧做法是"图多大、条带剩多少就用多少"——条带高度随图比例在 150~555px 之间乱跳，文字位置每次都要重算，模板没法预制。

新做法是**先把中间挖一个固定大小的洞，图 contain 进洞**：

- 洞宽恒为 1080（满宽）
- 洞高由模板固定
- 图按 `min(1080/w, 洞高/h)` 等比缩放，在洞里居中

结果：**版面是常量，图是变量**。三套模板可以预渲染成静态 PNG，文字位置永不抖动。

---

## 二、为什么洞高最大只能是 1440

洞高不是"越大越好"，它被条带高度反推：

```
条带高 = (1920 − 洞高) ÷ 2
```

而 240px 是条带能放下"品牌行 + 细线 + 标题"的下限（打样验证：240 时标题 85px，再薄就得压到 60px 以下）。

代进去：

```
洞高最大 = 1920 − 2 × 240 = 1440     ← 恰好等于 3:4 图满宽后的自然高度
```

所以 **1440 不是选出来的，是 240 条带反推出来的唯一解**。这也是个巧合的好结果：手机竖拍最主流的 3:4 图放进去满宽满高，一点不缩。

反面验证：洞高 1500 时，2:3 图能从 960 宽救到 1000 宽（+4%），但条带从 240 压到 210、标题从 85px 掉到 75px。**用主流比例的版面换冷门比例的 4% 宽，不划算。**

## 三、三套模板

| 模板 | 洞（宽×高 @ y） | 条带 | 标题 | 吃哪些比例 | 图占画布 |
|---|---|---|---|---|---|
| A 竖图 | 1080 × 1440 @ 240 | 240 | 85px | 4:5 / 3:4 / 2:3 / 9:16 | 高 75.0% |
| B 方图 | 1080 × 1080 @ 420 | 420 | 132px | 5:4 / 1:1 / 4:5 | 高 56.3% |
| C 横图 | 1080 × 0810 @ 555 | 555 | 132px | 3:2 / 4:3 / 16:9 | 高 42.2% |

**选模板规则**（按原图 `r = w/h`）：

```
r ≤ 0.82  → A   （4:5 及更竖）
r ≤ 1.22  → B   （5:4 ~ 4:5）
r > 1.22  → C   （更横）
```

**实测**（六张真实素材，全部宽 100%）：

| 原图 | 模板 | 图落位 | 占画布 |
|---|---|---|---|
| coffee 907×1209 (3:4) | A | 1080×1440 | 100% × 75.0% |
| bakery 907×907 (1:1) | B | 1080×1080 | 100% × 56.3% |
| breakfast 907×680 (4:3) | C | 1080×810 | 100% × 42.2% |

比 3:4 更竖的图在 A 里会缩（唯一的例外，物理必然）：

| 比例 | 落位 | 占宽 |
|---|---|---|
| 2:3 | 960×1440 | 88.9% |
| 9:16 | 810×1440 | 75.0% |

## 四、图片处理：只有一次 resize

不裁、不拉伸、不调色、不加锐化、不加噪点、不加暗角。

```
k = min(1080 / w, 洞高 / h)
```

这是"用户上传什么就是什么"的硬保证。之前所有方案（海报版要裁、全出血要裁 25–58%、方式三要透视贴图）都在这一步动了图，模板方案不动。

## 五、分工：模板管材质，程序管文字

| 谁 | 负责 | 原因 |
|---|---|---|
| 模板（AI 生成，预制 PNG） | 深底色、纸纹/布纹、装饰线、图区边缘的收边 | 静态、可复用、零运行成本 |
| 程序（SVG 合成） | 品牌行、标题、副标、说明、编号、地址 | 文案每次不同，必须参数化 |

**模板上不能有文字。** 文字一旦烧进背景图，文案就改不了了。

文字层四档透明度（不引入灰色，深底上白字调透明度就是灰阶）：

```
标题 1.00 / 品牌 0.86 / 说明 0.74 / 副标 0.52 / 编号 0.40 / 地址 0.28 / 细线 0.16~0.20
```

## 八、为什么放弃海报版面

| 判据 | 海报版面 | 固定模板 |
|---|---|---|
| 动图吗 | 不裁，但要用"面板"框住图 | 完全不裁不缩，只 resize |
| 条带高度 | 由图比例决定，150~555 乱跳 | 模板固定，文字位置不动 |
| 可预制 | 每种比例一套参数，还要算明暗分支 | 三张静态 PNG，一次做完 |
| 白底/实景图 | 需要两套版式（面板版 / 全出血） | 一套通吃，图不参与设计 |
| 商品占画布 | 4:3 = 42.2% / 1:1 = 50.2% / 3:4 = 49.8% | 4:3 = 42.2% / 1:1 = 56.3% / 3:4 = 75.0% |

最后一行是关键：**模板方案在每种比例上都 ≥ 海报版面**，因为它不裁、也不留版面边距，图的宽度直接吃满 1080。

## 九、排版引擎：为什么必须把文字转成路径

**踩到的坑**：`sharp` 的 SVG 渲染器**不认任何 `font-family`**。实测 21 个家族名（SimSun / KaiTi / Palatino / Georgia / 项目自带的站酷系列），渲染结果**逐像素完全相同**——全部 fallback 到同一个兜底字体。

这解释了之前一直用 `font-family="XW"` 也能出字：不是 XW 存在，是它根本没被解析。

**解法**：把字形取成矢量路径再画，绕开 `font-family`（`storage/tmp/contain/v6/type.mjs`）。

### 三个必须记住的坑（全部实测）

**一、不能用 opentype.js 解析思源系列。**
它解析 3 万字形的大字体时，对部分左右结构的合体字会丢掉一个部件——实测「咖」只剩「加」，左边的「口」整块消失。三个渲染器（librsvg / resvg / Chrome）在同一份路径上掉的都是同一块，所以问题在解析库，不在渲染器。换成 `fontkit` 后同一字完整。

**二、每个字必须输出独立的 `<path>`。**
把多个字的轮廓拼进同一个 `d` 属性，部分汉字的子轮廓会被渲染器丢弃。换渲染器不解决，只能拆开。附带好处：逐字动效变得可行。

**三、fontkit 的坐标是 y 轴向上（数学坐标），SVG 是 y 轴向下。**
纵向缩放必须取负：`path.scale(s, -s)`。忘了这一步，整行字会上下颠倒。

**系统字体全部作废。** 仿宋、楷体、等线、Bodoni、Futura 都是 Windows 自带，版权不可随产品分发，更不能用于给付费用户出片。已在 `materials/fonts/index.json` 的 `bannedSystemFonts` 里显式登记并标注替代字体——留这条是为了防止以后有人图方便又接回系统字体。

**日文明朝体不能用**（缺 11 个常用简体字：咖、啡、奶、现、烤、糕、饮、每、厅、馆），但换成思源宋体后这个问题已不存在。

### 字体选型与字号的对应关系（已修正）

原结论"80px 以上必须无衬线"是**针对仿宋**得出的，不适用于思源宋体：

- **96px** → 思源宋体 300 同样成立（样张实测），不必强制无衬线
- **80px 以上** → 仅仿宋不可用，这是仿宋的问题不是衬线的问题
- **20px 以下** → 仍然必须无衬线，衬线在深底 + 低透明度下会糊

### 随机抽字体的正确做法

**不抽单个字体，抽配对。** 字体混搭会崩：马善政楷书配 Playfair 和谐，站酷快乐体配思源宋体就是灾难。随机只能在预设组合里随机。

见 `scripts/font-pick.mjs`：8 套配对 + 6 个角色池 + seed 复现（同一订单重出必须同字体，否则用户改个错字重出一次整张片子换风格）。

**2026-10-23 第二次改动：版式与配对彻底解耦，共 18 组有效组合。**

之前这张表写的是"哪套版式用哪几款字体"，那是错的架构。五套版式的字体被 `LY_F` 五个常量写死，后果有两个：①选版式就等于定了字体，用户在「字体配对」里换字对版式毫无作用；②8 套配对里 4 套在版式上没有入口，站酷三款字体入库后一个版式都用不上。

现在分成两层：**版式管"放哪、多大、对齐哪边"，配对管"用什么字"**。版式里不再出现任何字体名，只有三个角色——

| 角色 | 用在哪 | 来源 |
|---|---|---|
| `F.display` + `F.displayWeight` | 中文大标题 | 配对的 `display` / `displayWeight` |
| `F.latin` + `F.latinWeight` | 英文小标、编号、站名 | 配对的 `latin`，字重按该字体实际有的取 |
| `F.micro` | 说明行 | 配对的 `micro`（恒为思源黑体 400） |

**为什么不是 5×8=40 全排列，而只开 18 组。** 剩下的 22 组是排不出来，不是不好看：T5 竖排离开书法或纤细宋会变成菜单排版，T2 贴顶网格塞圆胖体会直接散架。所以每套版式带 `allowed` 白名单，选择器只列白名单内的；同时每套配对至少要有一处去路（`v4-check.mjs` 第 9 组测试守着）。性格强的三款自然只有一两个去处——马善政只配竖排，黄油体只配画册/片头，快乐体只配大留白。

**换字会引出"墨迹高度"这个隐藏变量。** 同一个字号下，黄油体/快乐体的字面比思源宋高近 20%，T3 双线夹标题的基线写死后，换一款字就顶到装饰线上。解法是给每款显示字体一个墨迹系数 `DISPLAY_INK`（思源黑 0.80 / 思源宋 0.82 / 小薇 0.86 / 马善政与黄油 0.95 / 快乐 1.00），基线按"文字墨迹在夹带里视觉居中"反算：`基线 = 带中线 + 字号 × ink / 2`。副作用是思源宋的基线也从 184 挪到 194，原来上下是 38/48 不对称，现在是 38/38。

**拉丁字重不能硬写 500。** Jost 有 400/500，Playfair 只有 400/700。T4 的宽字距小标想要 500，Playfair 没有就退回 400——硬写 500 浏览器会合成假字重，笔画发胖，这是"看起来有点怪但说不上哪里怪"的典型来源。

**这张表在 2026-10-23 还做过一次字体迁移**：原来写的是 Bodoni / 等线 / 仿宋 / Futura / 楷体，全是 Windows 自带字体，既不可商用、也不该出现在给付费用户的成片里。替换一律按 `materials/fonts/index.json` 的 `bannedSystemFonts.replacements` 反查，不是重新选型。

## 十二、V4 实验室集成（`docs/visual-gallery/v4.html`）

五套版面已作为独立分类「版面排版」接入 V4，可与任意商品图搭配即时预览，不再需要预先渲染成片。

### 洞位自动选择（用户不选）

| 图片比例 r = 宽/高 | 洞位 | 洞高 | 条带 |
|---|---|---|---|
| r ≤ 0.82（3:4、2:3、9:16） | A 竖图洞 | 1440 | 240 |
| 0.82 < r ≤ 1.22（1:1、5:4） | B 方图洞 | 1080 | 420 |
| r > 1.22（4:3、3:2、16:9） | C 横图洞 | 810 | 555 |

### 一套参数吃三种洞位的换算

```
k     = 条带高 / 240
顶部条带元素   y' = y × k
底部条带元素   y' = (1920 − 条带高) + (y − 1680) × k
字号           size' = clamp(size × k, 下限, 上限)
```

字号必须封顶（T1/T2 大标题 150、T3 仿宋 110、T5 竖排 72）。不封顶时 C 洞位（k = 2.31）会把标题推到 203px，横图的标题比竖图还大，与"横图商品占比小、文字也不该喧宾夺主"的判断相反。

**已验证**：`storage/tmp/v4layout/check.mjs` 对 3 洞位 × 5 套做几何校验——所有元素落在 1080×1920 内、顶部元素不越过洞顶、底部元素不越过洞底、单行文字不越左右轴线（66 / 1014）。**15 组全部通过，0 问题**。这条检查值得保留，因为"文字压到商品图上"是这套版式最容易犯且最致命的错误，肉眼看缩略图很难发现。

### 2026-10-23 改版：V4 接入真实字库（不再有系统字体）

之前这一节记的是"等线 Light 要用 font-weight 300 取"，那是系统字体时代的问题。现在五套版式全部走 `materials/fonts` 的 13 个 OFL 文件。接入方式经过一次返工，最终定成「子集化内嵌」，理由在第三条。

**一、13 面 `@font-face` 全部是内嵌 data URL，由 `scripts/build-v4-fonts.mjs` 生成。**

```css
/* ===== V4FONTS:BEGIN 由 scripts/build-v4-fonts.mjs 生成，勿手改 ===== */
@font-face{font-family:'Noto Sans SC';font-weight:300;font-style:normal;font-display:swap;src:url('data:font/woff2;base64,d09GMg...') format('woff2')}
/* ===== V4FONTS:END ===== */
```

家族名必须用注册表里的裸名（`Noto Sans SC`），不要自造 `V4 Noto Sans SC` 这类前缀。理由很实际：`document.fonts.load('300 16px "Noto Sans SC"')` 用的是裸家族名，自造前缀会让加载校验查不到、静默返回空，于是"校验通过但字体没生效"。

**二、同一家族的每个字重必须是独立文件、独立 `font-weight`。** 思源宋体 300/400/700 是三个 ttf，不声明 `font-weight` 会让浏览器只认最后一条，标题与正文全变同一粗细——和当年"等线 Light 变 Regular"是同一类错误，只是来源从系统字体换成了自己的声明。

**三、为什么必须内嵌，而不是引用 `../../materials/fonts/*.ttf`。**
第一版用的是外部相对路径，`file://` 双击实测 13 面全部 `status=loaded`，看起来没问题。但 V4 还有第三种打开方式——IDE 的静态预览面板会把 HTML 单独拷到 `static-html/<hash>/` 下服务，此时 `../../materials` 落到 `http://host/materials/`，**实测 404**，字体全部静默回退到系统字体。画面不报错，只是"细体变常规体"。既然这种失败不可见，就不能依赖路径，唯一稳的办法是把字体装进文件自己身上。

**四、内嵌的是子集，不是完整字库。** 85MB 原文件塞不进来，脚本先从页面提取全部字符（当前 796 字，含中文 701），再用 `pyftsubset` 压成 woff2：13 面合计 1.27MB，页面 1.9MB。**改任何文案（`LY_COPY`、字体描述、CTA 文案）都必须重跑 `node scripts/build-v4-fonts.mjs`**，否则新字缺字形。`v4-check.mjs` 会用 fontkit 逐面读 woff2 的 cmap 校验"页面每个中文字都有字形"，漏了直接红。

**加载失败必须报出来。** `verifyFonts()` 在初始化时逐面 `document.fonts.load`，失败时状态栏红字提示，而不是安静地回退到微软雅黑。静默回退是这套东西里最难发现的问题：画面不会报错，只是"高级感"没了。

### V4 新增两个类目后，与真实资产的对应关系

| V4 类目 | 真实来源 | 数量 | 用途 |
|---|---|---|---|
| 字体字族 | `materials/fonts/index.json` 的 `fonts[]` | 8 款 / 13 文件 | 逐款看字形、字重、覆盖率、授权 |
| 字体配对 | 同上 `pairings[]` | 8 套 | 出片引擎的实际抽取单位，配 seed 复现 |

**字体配对是抽取单位，不是排版建议。** `scripts/font-pick.mjs` 只抽配对不抽单个字体——马善政楷书配 Playfair 和谐，站酷快乐体配思源宋体是灾难。V4 里那个 SEED 输入框复刻的是同一套 FNV-1a + mulberry32，`order-8848` 在页面里和在 Node 里都落在"文艺清秀"，这一点由 `v4-check.mjs` 的 `drawPairing` 断言守着。算法一旦两边漂移，实验室里看到的效果就不是生产出的效果。

**分类计数全部派生自资产表长度**（`categoryCount`），不再写死。写死的结果是三个数互相打架：页面写 6、注册表 8、`materials/index.json` 写 56。后者的 56 是招商目标，已改名为 `plannedCount`，实入数单独记 `installedCount`。

### 实验室内的实现约定

- **排版层是透明 SVG**，`viewBox="0 0 1080 1920"`，`z-index:4`——在商品图之上、比例示意框之下。只有文字和线条，不遮挡商品。
- **选中版面后商品图改按洞位 contain**（`fitProductBox(w,h,slot.h)`），否则画面上看到的条带高度是假的，与成片不一致。
- **再次点击同一项即取消**，用于和"无版面"直接对比。取消后图片恢复整幅 contain。
- **示例图内嵌为 data URL**（3 张：3:4 / 1:1 / 4:3，共 121KB），点「载入示例图」即可看到三种洞位。不发请求、不上传，符合 V4 "仅本地读取"的约束。
- **画布从 320px 放大到 420px**。320px 下 20px 的说明行只有 5.9 个 CSS 像素，等于看不见；420px 下是 7.8px，勉强可辨。这是"看排版"这个用途的下限，再小就只剩构图比例可看。
- **预览用 `font-family`，生产用转路径。** 浏览器里直接写 `font-family` 就行；出了这个页面走 sharp/resvg 时必须转成矢量路径（第九节三条坑）。两边不是同一套实现，别想着统一。
