## 一、 为什么反其道而行之：不做“小剪映”，拒绝“假面数字人”

在立项之初，很多同行劝我：“做视频工具，你得加多轨时间轴、加关键帧拖拽、加花里胡哨的特效贴纸，或者直接上会扭腰眨眼的数字人。”

但我深入调研了几十位真正每天要靠短视频卖货的实体店主、电商小卖家和档口老板后，发现了一个巨大的断层：

1. **多轨道时间轴对于普通店主是巨大折磨**：绝大多数商家根本搞不懂什么是帧率、什么是转场轨道、什么是音画对齐。他们打开剪映，面对几十个按钮只觉得头大。
2. **模板工具产出的视频廉价且千篇一律**：套用大红大绿土味模板的视频，完播率极低，根本无法建立高端专业的品牌信任感。
3. **数字人是高成本伪需求**：生硬假脸不仅渲染极度吃显卡算力，而且在真实带货场景下一眼假，甚至会遭到平台的限流与违规处罚。

**真正能解决痛点的解法只有一个：极简 3 步，10 秒出片。**
> 商家用手机随手拍 3~9 张商品实拍图或几段原声视频 -> 挑选主播表达情绪风格 -> 点击合成，系统自动搞定分镜运镜、文案剧本、TTS 语音、避让混音与合规片尾，直出 1080×1920 商业级短片。

## 二、 核心技术架构与技术选型

整个项目采用 Monorepo 大工程架构，保持高内聚低耦合：

```text
├── apps/
│   ├── web/client      # 前端 Web 客户端（极简黑曜石设计系统）
│   ├── web/server      # BFF 接口服务层（Node.js 网关 / 调度 / 并发风控）
│   └── admin           # 企业管理后台
├── packages/
│   ├── image-film      # 图片成片引擎（导演剧本编排、TTS 逐镜实测对齐）
│   ├── video-dub       # 视频配音引擎（Single-Pass 极速流式转码）
│   ├── speech-cut      # 出镜口播引擎（气口停顿消除、双机位跳切补偿）
│   ├── audio-kit       # 音频混音引擎（情绪选曲、Sidechain 动态避让）
│   ├── subtitle-kit    # 字幕渲染中台（发丝级微距字幕、国标 AIGC 元数据注入）
│   ├── ending-kit      # 结尾收束中台（15 款定稿 CTA 骨架、国标标识内联）
│   └── ffmpeg-kit      # 音视频渲染基建（硬件加速感知、并发闸门）
```

### 1. 前端视觉哲学：黑曜石毛玻璃与“0 Emoji 绝杀令”
在 UI 设计上，我彻底摒弃了消费级 SaaS 常用的廉价实心白底大药丸按钮，全站确立了四项铁律：
- **全站 0 Emoji**：绝不滥用系统表情符号，统一采用微型矢量 SVG（如 9×9 微三角）与发丝细线；
- **2px 倒角微光幽灵边框**：`background: rgba(255,255,255,0.025); border: 1px solid rgba(255,255,255,0.2);`，悬停时产生冷白辉光；
- **全页面半透明通透体系**：`rgba(10, 10, 14, 0.6)` + `backdrop-filter: blur(20px)`，确保背景视频流动质感穿透工作台；
- **4 级大厂文本对比度规范**：高光白、银灰至铅灰，彻底消灭对比度低于 65% 的脏灰色。

## 三、 音视频底层踩坑实录：三个硬核工程攻坚

### 1. 从 26.95 秒到 8.63 秒：Single-Pass 复合滤镜直出
初期实现视频配音与图片成片时，常规做法是**多遍分步处理**：
> 第一步先裁切缩放 -> 第二步落盘临时文件 -> 第三步贴字幕 -> 第四步落盘 -> 第五步拼接片尾收束 -> 第六步混音输出。

这种做法在本地测试没问题，但一旦放到生产环境：
- **磁盘 I/O 瞬间打满**，连续读写造成极高的延迟；
- 中间过渡垃圾切片极难管理，容易引发磁盘爆满导致服务崩溃。

**重构解法：构建 Single-Pass 单遍复杂滤镜图（Complex Filtergraph）**。
我们将**缩放裁剪、开场电影级渐变黑羽化遮罩、发丝微距字幕渲染、片尾 15 款定稿 CTA 动态叠合**，全部收敛在同一个复合滤镜流水线中一次性流式计算完成，彻底干掉所有中间临时磁盘落盘文件。
实测结果：**单视频渲染耗时由 26.95s 腰斩至 8.63s，提速 68%！**

### 2. 真实双段式 Sidechain 动态人声避让混音
普通视频剪辑最让人头疼的就是背景音乐（BGM）和人声旁白打架。
简兮在音频处理中实现了两段式 Sidechain 动态人声避让混音链：
- 当识别到有人声旁白波形时，通过 `sidechaincompress` 滤镜将 BGM 毫秒级平滑压低至 -22dB；
- 当人声停顿时，BGM 在 200ms 内平滑淡入回弹至正常动态范围；
- 片尾收束 CTA 阶段，BGM 再次渐弱淡出，保证行动号召掷地有声。

### 3. iPhone HDR BT.709 色彩矩阵对齐
大量店主使用的是 iPhone 实拍的原生视频（杜比视界 / HLG / BT.2020 广色域）。当用常规的 FFmpeg 转码为 Web 标准的 H.264 时，成片会出现极其严重的**“画面发灰、对比度发蒙、高光过曝”**。
我们在转码入口强制引入色彩空间感知与矩阵重映射：
```bash
colorspace=all=bt709:trc=bt709:space=bt709:primaries=bt709:fast=1
```
在流式转码阶段强制将广色域曲线平滑映射回 SDR 标准 BT.709，彻底还原商品本身的质感与色彩饱和度。

## 四、 商业落地的灵魂：“商业出片五件套”闭环

视频合成完就结束了吗？远没有。
小商家拿到一个 mp4 文件，依然不会发小红书、不会发视频号、不会写标题。

因此，简兮确立了**商业交付五件套（Commercial Launch Kit）**闭环：
1. **纯净宣发封面海报**：0 台词字幕、0 AI 角标的超清抓帧图，直接可用作小红书/抖音封面；
2. **高转化爆款文案**：根据商家填写的核心卖点与人设风格，大模型自动输出契合平台算法的内容文案；
3. **封面吸睛大字**：提取 4~8 字直击人心的封面悬念词；
4. **黄金置顶引流评论**：提前拟定引导用户互动、私信或领券的第一条评论；
5. **广告法合规过滤**：自动过滤“国家级、最先进、绝对保真”等违禁极限词，帮店主规避下架封禁风险。
