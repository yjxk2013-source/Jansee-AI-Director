## 一、项目一句话定位

全栈 AI 短视频生产工场（Monorepo）：商家丢商品图/视频 → 四大核心版块出成片（1080×1920 竖版）+ 发布方案五件套 + 片尾收束卡。全流程 LLM 导演写台词、TTS 配音、ffmpeg 渲染。

- **双仓库**：GitHub `origin` + Gitee `gitee`，推送 main 必须双推。
- **当前版本**：`v3.5.0`（2026-11-13 已双推，工作区干净）。
- **本地环境**：4 核 4GB Windows 机，ffmpeg 渲染 CPU 打满是性能墙；目标上云 4C4G。

## 四、最近一轮工作（2026-10-24 ~ 10-25，已全部提交双推）

### 1. 主播风格层（5c0923e）
变体导演 × 主播锚点排班：台词 DNA + 语速档位全链路。两个已修的真 bug：
- LLM 返回裸字母变体名（'D'）→ `normalizeVariantType(v, scene)` 前缀补全（80fe0c8）。
- 黑名单轮转饥饿（G 型兼容主播全被拉黑）→ 末跳改全池 `HOST_LIBRARY` 找兼容者（facbdc5）。原则：**兼容性是正确性约束，轮转是公平性机制**——放行不兼容主播是错误，宁可不轮转。

### 2. AI 标识合规（GB 45438-2025，9f0d38a + bb3a2ca）
- **单一真源** `packages/subtitle-kit/aiBadge.js`：显式（两段式：开头「AI 生成」2.5s + 尾部含 JANSEE 宣传位）+ 隐式（ffmpeg 元数据 9 字段，`movflags +use_metadata_tags`，平台算法判 AIGC 防限流）。drawtext 路线（4 视频链路）与 PNG 路线（图片成片）都从共享层出。
- 字体恒命中思源黑 Regular（曾误判微软雅黑 Light，教训：只读函数一半就下结论）。

### 3. 性能与进度（487e4d0 / 0b97175）
- **真实进度条**：ffmpeg `-progress pipe:1` 消费 `out_time_us`，渲染段 46→99 连续爬升；不再虚标。
- **编码定版**：veryfast/crf23/**24fps**，渲染 -31%，体积 -25%。基准：30fps medium/crf20 36.2s → 24.9s。平台转码主要压码率不压 FPS，24fps 无惩罚。

### 4. 清理定案（4fb6145）
- LLM 返回死字段全删（emotion/sfx_on/opening/ending/cover_line/visual_design/duration/pause_after 图片分支/motion/transition 视频分支）。
- `recordCreative` 防重账本断线修复（旧路由收敛时断，接回 creation.mjs 两完成点）。
- 图片成片时长铁律重申：每镜 = TTS 实测 + 0.7s（LLM 是执行层，时长认证定）。

### 5. BGM 全域均衡轮巡与 LFU 持久化防重（v3.2.2 定版）
- **核心痛点根治**：彻底消除服务重启轮转清零、同音不同名 51 组跨目录撞车、以及部分常规情绪与冷门曲目长尾遗漏问题。
- **LFU 最小播放次数优先**：候选曲目优先挑累计 `playCount` 最低的一档；全池/本情绪所有独立曲目必须 100% 均播过 1 次后才进入第 2 轮，数学上杜绝死角。
- **音频 MD5 指纹排重 + 近期避让**：以音频文件二进制 MD5 作为唯一指纹，同曲跨目录自动标记；全局最近 20 首播过的曲目哈希物理剔除避让。
- **播放账本落盘持久化**：统一落盘在 `bgm_history.json`，服务重启与重新发版不丢失已播计数。
- **口播与分镜直出放开**：打破原先死锁在 `relaxed` 单目录 20 首的限制，扩充至 8 大常规百搭情绪大池（`relaxed`, `fresh`, `warm`, `cozy`, `playful`, `inspirational`, `energetic`, `calm_narrative` 共 160 首），按各情绪平均播放次数均衡轮流调用。
- **导演层跨任务避让升级**：`director.mjs` 扩充读取最近 5 次成片情绪，显式提示 LLM 避让近期高频基调，向冷门常规情绪扩散。

## 五、性能现状（本地 4C4G 实测）

| 指标 | 数值 |
| :--- | :--- |
| 图片成片单条渲染 | 60.25s → **31.0s**（-49%，逐像素不变） |
| 并发 2 双任务总耗时 | 242.5s(30fps) → **146s**（-40%） |
| 单用户单条全链路 | **91s**（LLM/TTS 等网络 ~25s + 渲染 ~60s） |
| 内存峰值 | 恒 3.68-3.72GB（4GB 机贴上限；单 ffmpeg 峰 800+MB） |

**并发池语义**：池=2 是上限非开销，单任务自动退化并发 1；并发 2 用 B 片渲染填 A 片网络空窗，两条总耗时快 19%。**保持池 2 不动**。

**剩余优化三张牌（定调：先不动，等上云真实耗时或多版流量信号）**：①快档 LLM 模型 ②预合成单层化（动发动机，油箱还剩 ~25s）③首镜预览。

8. **AI 台词永远用户手选**：自动检测只能判断素材是什么样，判断不了用户想要什么。

## 十、沟通口径（与用户协作方式）

- 人话版，先结论后理由，术语先翻译；要单一决断（推荐什么/为什么/最大风险），厌恶多选项纠结。
- 严格按用户的分层顺序走，不提前跳层；每轮在当前层收敛。
- 独立判断：用户想法是参考不是答案，方向不对直说；结果第一，不为沉没成本维护旧方案。
- 提示词/宪法层面的改动先讨论再动手（用户习惯「先不动代码，讨论阶段」）。
